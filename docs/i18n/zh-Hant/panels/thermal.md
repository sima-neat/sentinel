# 熱感應面板

熱感應面板報告了 17 個溫度通道：

- 在 Modalix SoC 內部有 14 個片上 RTSN/PVT 通道；
- 由一個與 LM96163 相容的裝置回報的兩個 SOM 板溫感測通道。
  硬體監控裝置；
- 一個乙太網路/MDIO 硬體監測通道。

所有數值均為攝氏度。這些是感測器位置的點測量值，而非環境空氣溫度，也非平均晶片溫度。

## 最高溫度

頂端圖表會選取每個快取樣本中，所有熱度指標的最大有限溫度。最熱的感測器可能會在不同樣本之間變動。請使用個別感測器的圖表來識別來源。

## 整合於晶片上的 RTSN/PVT 感測器

Sentinel 會透過 `/dev/mem` 映射 PVT 控制器，觸發每個通道，並使用以下方式將其原始的 12 位元格式讀取值轉換為：

```text
temperature_C = raw × 698.9 / 4096 - 283.0
```

這個系統單晶片 (SoC) 具有七個實體位置。每個位置都由一個警報通道的 RTSN 和一個觸發通道的 RTSN 在相同的位置表示：

| 地點 | 警報頻道 | 行程頻道 |
| --- | --- | --- |
| MLA 象限 Q0 | `MLA-0` | `MLA-7` |
| MLA 象限第一象限 | `MLA-1` | `MLA-8` |
| MLA 象限第二象限 | `MLA-2` | `MLA-9` |
| MLA 象限第三季 | `MLA-3` | `MLA-10` |
| APU | `APU-4` | `APU-11` |
| CVU | `CVU-5` | `CVU-12` |
| 頂部，靠近 PCIe/乙太網路插槽 | `TOP-6` | `TOP-13` |

這兩個數值並非代表顯示值中兩個不同的溫度上限。它們代表兩個感測器通道，分別向同一位置的硬體閾值路徑提供訊號。預期這兩個數值之間會有輕微的差異。

如果 RTSN 採樣失敗，Sentinel 會記錄失敗訊息，並在後續的常駐程式過程中停用該 RTSN 採樣器。在修正 `/dev/mem`、權限或硬體存取問題後，重新啟動常駐程式。

## 板載式和乙太網路感測器

| 顯示名稱 | 來源 | 實體解釋 |
| --- | --- | --- |
| `LM96-1` | `lm96163` `temp1_input` | 來自監測 IC 內部感測器的系統模組（SOM）頂部電路板溫度。 |
| `LM96-2` | `lm96163` `temp2_input` | 從位於系統模組（SOM）底部的二極體測量 SOM 底面的溫度，並透過監測 IC 讀取。 |
| `ETH-1` | 乙太網路/MDIO `temp1_input` | 以太網路硬體監測裝置所回報的溫度。目前尚未確認確切的實體元件。 |

Linux 的 hwmon 報告以毫攝氏度為單位；Sentinel 將該值除以 1000。
由於 `hwmonN` 的編號可能會變更，因此 LM96163 目錄會透過驅動程式名稱來解析。顯示的範例路徑並非穩定的識別碼。

## 顏色和閾值

- 青色：低於 45°C
- 綠色：45°C 到 70°C 以下。
- 紅色／警告：70°C 至低於 85°C
- 粗體紅色／嚴重：85°C 或更高

這些是「Sentinel」的演示閾值。它們不會取代裝置規格表中的限制、熱保護觸發行為或特定板卡的作業需求。
