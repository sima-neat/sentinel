# 電源面板

Sentinel 在專用的執行緒中，每 250 毫秒從核心的 PMBus 驅動程式讀取每條電源軌的輸出功率（`POUT`）。由於一般的快取間隔較長，因此使用者介面會發布最新的累積狀態，而不是顯示每個電力讀數。

## 來源

每條電源軌都是 PMBus 穩壓器 hwmon 裝置的一個 `pout` 通道：`/sys/bus/i2c/devices/<bus>-<address>/hwmon/hwmon*/power<N>_input`，單位為微瓦，其中 `power<N>_label` 為通道命名（例如 PMBus 第 0 頁為 `pout1`）。Sentinel 依 I2C 位址尋找裝置、依標籤尋找通道，絕不依 `hwmonN` 或通道編號尋找。核心驅動程式會在自己的鎖定下選擇 PMBus 頁面並讀取暫存器，因此其他讀取穩壓器的程式無法破壞 Sentinel 的讀數。

在 Modalix 上，穩壓器是 IRPS5401 裝置。裝置樹已宣告這些裝置，但 `irps5401` 模組不會自動載入，因此 Sentinel 服務會在啟動前執行 `modprobe irps5401`。未綁定驅動程式時，無法取得電力資料，收集器錯誤會指出需要載入的模組。

## 標題欄位

| 欄位 | 計算 |
| --- | --- |
| 目前 | 最新一輪中所有已設定電源軌的總和。任何電源軌無法讀取時為空白。 |
| 會期平均值 | 自守護程式啟動以來，所有完整輪次總和的算術平均值。當每條電源軌都已讀取時，該輪次即視為完整。 |
| 會話高峰 | 自守護程式啟動以來，完整輪次總和的最大值。 |
| 時長 | 自電力累積器開始運作以來經過的單調時間。 |
| 有效的樣本 | 所有已設定電源軌都已讀取的輪次。 |
| 檢測失敗的樣本 | 至少有一條已設定電源軌無法讀取的輪次。 |

每次重新啟動守護程式時，所有會話統計資料都會重設。

## 收藏家聲稱

- **處於作用狀態**：至少存在一個完整輪次，且最新一輪已讀取
  所有電源軌。
- **品質降低**：存在完整輪次，但最新一輪至少有一條電源軌
  無法讀取。
- **無法取得**：尚未收集到任何完整輪次。

Sentinel 絕不會將較早的讀數顯示為目前值。當某條電源軌無法讀取時，其 Power 值和「目前」值會保持空白，直到下一次成功的輪次；「失敗的樣本」與該電源軌的「錯誤」會增加，狀態會變為「品質降低」。「平均值」和「峰值」只包含完整輪次，因此每個總和都涵蓋相同的電源軌。

## 鐵路表格欄位

- **Power** 是該電源軌在最新一輪中的讀數；若該次讀取失敗
  則為空白。
- **樣本數**：統計自守護程式啟動以來，該軌道成功讀取的次數。
- **錯誤** 欄位會計算讀取該電源軌的核心 `power<N>_input` 檔案失敗的次數，例如在未綁定驅動程式時。

## Modalix SOM 鐵路

| 鐵軌 | 它提供什麼？ |
| --- | --- |
| `SoC and DDR VDD` | 主要系統單晶片 (SoC) 和 DDR 領域；SoC 邏輯、記憶體控制器和 DDR 活動均有所貢獻。 |
| `HDMI 1.2V` | HDMI 1.2 版的 PHY 以及相關電路。 |
| `SoC and DDR VDDQ` | 記憶體控制器與 DDR 裝置之間的 DDR I/O 訊號域。 |
| `SoC and DDR VDD2H` | 額外的系統單晶片 (SoC)/DDR 記憶體電源域。 |
| `MLA 0.68V` | 0.68V 的 MLA 核心供電以及與 MLA 運算最直接相關的電壓軌。 |
| `PCIe and ETH VP` | PCIe 和乙太網路 PHY/平台領域。 |
| `SOM Platform 1.8V` | 共享 1.8V SOM 平台和周邊電路。 |
| `SOM Platform 3.3V` | 共享 3.3V SOM 平台和周邊電路。 |

`SoC and DDR VDD` 和 `MLA 0.68V` 的報告步驟為 0.25 W。其他標準 SOM 電壓軌的步驟為 0.03125 W。因此，在樣本數量增加且錯誤為零的情況下，`0.00 W` 是一個有效的零值暫存器讀取值，表示在該電壓軌的解析度下，讀取值為零，而不是感測器讀取失敗。

Modalix DVT 設定檔僅顯示 `DVT PMIC 0x4d page0`。其總值不能直接與八個電壓軌的 SOM 總值進行比較。

## 測量邊界

目前監測的是板載電源軌，而非交流市電或整個系統的輸入電源。它可以排除未監測的電源軌、穩壓器損耗、載板元件、儲存裝置、風扇和主機端裝置。

同樣地，模型能量並非僅由 `MLA 0.68V` 來表示。推論還會使用 DDR、SoC 和平台電源軌。在比較不同執行結果時，請記錄設定檔、電源軌健康狀況、Sentinel 版本、工作負載時間範圍以及環境/板載條件。
