# 儲存和網路面板

「儲存/網路」面板會顯示根 eMMC 的容量和整個裝置的 I/O 效能，以及選用的 NVMe 儲存裝置（位於 `/media/nvme`）和彙總的非迴路網路計數器。

## 檔案系統容量

| 欄位 | 來源與計算方式 |
| --- | --- |
| 已使用的 eMMC 容量／已使用的 MB | `statvfs("/")` |
| 已使用的 NVMe 儲存空間／已使用的 MB | `statvfs("/media/nvme")`，只有當該路徑是掛載點時，才會生效。 |

Sentinel 計算：

```text
total = f_blocks × f_frsize
available = f_bavail × f_frsize
used = total - available
used_pct = used / total × 100
```

由於 `f_bavail` 是可供非特權程序使用的可用空間，因此已保留的檔案系統區塊會影響顯示的已用值。`MB` 使用二進位 MiB 轉換。

只有在偵測到 `/media/nvme` 作為已掛載的磁碟時，才會新增 NVMe 指標定義，這是在守護程式啟動時發生的。在掛載或卸載磁碟後，重新啟動 Sentinel，以確保可用的指標集與系統相符。

## 磁碟輸入/輸出

Sentinel 會從 `/proc/mounts` 中解析掛載點的父裝置區塊，從 `/proc/diskstats` 中讀取扇區計數器，乘以裝置硬體的扇區大小，然後將位元組差異除以經過的採樣時間。

因此，讀取/寫入速率描述的是整個父裝置區塊，而不僅僅是透過顯示的檔案系統存取的檔案。其他分割區或使用相同裝置的使用者也可能做出貢獻。

如果掛載點到裝置的解析失敗，Sentinel 將使用裝置名稱的推測法：

- eMMC：第一個完整的 `mmcblk*` 裝置；
- NVMe：第一個完整的 `nvme*` 裝置。

第一個樣本沒有先前的基準值，且報告的速率為零。
計數器重置和裝置更換都採用飽和減法來處理，
因此不會產生負速率。

使用者介面將速率標示為 `MB/s`，但計算方式是兩次除以 1024，因此實際上等同於 MiB/s。

## 網路欄位

| 欄位 | 計算 |
| --- | --- |
| 網路接收量 | 針對每個非迴路介面，將從 `/proc/net/dev` 取得的接收位元組變更總和除以經過的時間。 |
| 網路 TX | 針對每個非迴路介面，將從 `/proc/net/dev` 取得的傳輸位元組變更總和除以經過的時間。 |
| 網路圖表 | 接收端 + 發送端。 |

彙總內容包括實體介面、橋接器、VLAN、隧道，以及存在時的虛擬乙太網路裝置。因此，相同的流量可以在多個層級進行統計，例如在一個實體介面上統計一次，然後在一個橋接器上再次統計。這指的是系統介面的活動，不一定是外部線路的吞吐量。

為了產生一個增量值，介面必須在連續的樣本中存在。第一個網路樣本會報告零值。金鑰結尾是 `_mbps`，但單位是 MiB/s 的等效值，而不是每秒兆位元。
