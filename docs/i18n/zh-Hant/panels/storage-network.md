# 儲存與網路面板

「儲存/網路」面板會顯示根 eMMC 的容量和整個裝置的 I/O 效能，以及選用的 NVMe 儲存裝置（位於 `/media/nvme`），彙總的非迴路網路計數器，以及本機 AI 代理人的預設路由上行鏈路使用率。

## 檔案系統容量

| 欄位 | 來源與計算方式 |
| --- | --- |
| 已使用的 eMMC 容量 / 已使用的 MB | `statvfs("/")` |
| NVMe 已使用量 / 已使用 MB | `statvfs("/media/nvme")`，只有當該路徑是掛載點時。 |

Sentinel 計算：

```text
total = f_blocks × f_frsize
available = f_bavail × f_frsize
used = total - available
used_pct = used / total × 100
```

由於 `f_bavail` 是提供給非特權程序使用的可用空間，因此保留的檔案系統區塊會影響顯示的已用空間值。`MB` 使用二進位 MiB 轉換。

只有在啟動守護程式時偵測到 `/media/nvme` 已掛載時，才會新增 NVMe 指標定義。在掛載或卸載磁碟機後，重新啟動 Sentinel，以確保可用的指標集與系統相符。

## 磁碟輸入/輸出

Sentinel 會從 `/proc/mounts` 中解析掛載點的父裝置區塊，從 `/proc/diskstats` 中讀取扇區計數器，乘以裝置硬體的扇區大小，然後將位元組的變化量除以經過的採樣時間。

因此，讀取/寫入速率描述的是整個父裝置區塊，而不僅僅是透過顯示的檔案系統存取的檔案。其他分區或使用相同裝置的使用者也可能對此產生影響。

如果掛載點到裝置的解析失敗，Sentinel 將使用裝置名稱的推測方法：

- eMMC：第一個完整的 `mmcblk*` 裝置；
- NVMe：第一個完整的 `nvme*` 裝置。

第一個樣本沒有先前的計數基準，因此報告的速率為零。
計數器重置和裝置更換都採用飽和減法處理，
因此不會產生負速率。

使用者介面將速率標示為 `MB/s`，但計算方式是兩次除以 1024，因此實際上是 MiB/s 的等效值。

## 網路欄位

| 欄位 | 計算方式 |
| --- | --- |
| 網路接收 | 從 `/proc/net/dev` 取得的每個非迴路介面接收位元組變更總和，然後除以經過的時間。 |
| 網路傳輸 | 從 `/proc/net/dev` 取得的每個非迴路介面傳輸位元組變更總和，除以經過的時間。 |
| 網路圖 | RX + TX。 |
| 上行接收/發送 | 針對由 IPv4 預設路由選取的介面，計算接收/發送位元組的增量，然後除以經過的時間。 |
| 上行接收/發送使用率 | 以每秒位元為單位，表示方向性上行速率除以來自 `/sys/class/net/<interface>/speed` 的介面連線速度。 |

彙總包含實體介面、橋接、VLAN、隧道和虛擬乙太網路裝置（如果存在）。因此，相同的流量可以在多個層級上進行計數，例如，在實體介面上計數一次，然後在橋接上再次計數。這表示的是系統介面活動，不一定是外部線路的實際吞吐量。

為了計算增量值，介面必須在連續的樣本中存在。第一個網路樣本會報告零。鍵的結尾是 `_mbps`，但單位是 MiB/s 的等效值，而不是每秒兆位元。

本機 API 還會公開 `network_rx_bytes_per_second`、`network_tx_bytes_per_second`、`network_rx_utilization_percent` 和 `network_tx_utilization_percent`。這些明確的指標僅測量預設路由介面，從而避免彙總 UI 計數器中可能發生的重複計數。當 Linux 沒有報告正數的連線速度時（例如，對於某些虛擬或無線介面），則無法計算使用率。
