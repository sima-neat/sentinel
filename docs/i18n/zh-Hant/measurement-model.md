# 測量模型

Sentinel 將資料收集與顯示分開：

1. 這個守護程式會讀取硬體和 Linux 系統的計數器。
2. 它會定期使用暫存檔案來寫入 `/run/simaai-sentinel/cache.json`。
   檔案在建立後會立即進行原子重命名。
3. 終端使用者介面和報告指令會讀取該快取。它們不會進行取樣。
   直接修改硬體。

這種區別很重要：變更使用者介面 `--interval` 僅會變更快取顯示的頻率。它不會變更硬體採樣間隔。

## 預設的資料收集頻率

| 資料 | 預設頻率 | 備註 |
| --- | ---: | --- |
| PMBus 電力 | 100 毫秒 | 已彙集成一個專用的討論串。最新的、平均的、峰值、軌道計數器，以及錯誤狀態，將在下一次快取更新時發布。 |
| 熱感測器 | 獨立散熱迴路 | 迴圈在每次資料收集完成後會暫停 2 秒。讀取所有 RTSN 頻道也需要時間，因此實際的完整週期間隔會長於 2 秒。 |
| 中央處理器 (CPU)、記憶體、多層記憶體介面 (MLA) 記憶體、磁碟和網路。 | 2 秒 | 使用守護程式 `--interval`；最小可接受值為 0.5 秒。 |
| 流程 | 至少 5 秒 | 只有在常駐程式迴圈正常採樣系統指標時，才會檢查 5 秒的時限。在預設的 2 秒常駐程式間隔下，程序資料通常大約每 6 秒更新一次；如果常駐程式間隔超過 5 秒，則會變成有效的最小間隔。 |
| 終端使用者介面 | 0.5 秒 | 僅重新整理快取；它不會觸發資料收集。 |

預設情況下，這個守護程式會保留 240 個快取樣本。在預設的 2 秒快取間隔下，圖表會包含大約八分鐘的歷史資料。`daemon
--history N` 會變更保留的快取樣本數量。

## 標頭欄位

- **LIVE** 表示最新的快取樣本的建立時間小於 15 秒。
- **STALE** 指的是最新的樣本至少已經過 15 秒，或者樣本遺失。
- **age** 指的是自最新樣本的時間戳起算的經過時間。
- **samples** 指的是快取歷史記錄項目的數量，而不是 PMBus 的數量。
  熱敏式，或用於處理樣本。

即使是「即時」快取，也可能包含遺失或損壞的子系統。請使用子系統面板和匯出的狀態欄位，以區分快取的更新程度與感測器的健康狀況。

## 數值和圖表

- 標題或表格中的「值」來自 `latest.values`。
- 該圖表是根據保留的歷史資料中，該指標所產生的 `samples`。
- 收集到的非有限值會被序列化為 `null`。這取決於
  收集器：如果某個指標無法取得，則可以完全從樣本中省略該指標——例如，在取得第一個有效讀數之前，電源指標會不存在，且無法取得或已停用的 RTSN 頻道也會被省略。檢視器和匯出消費者必須處理指標不存在以及 `null` 值的情況；使用者介面會將這些顯示為 `-`、`unknown`，或根據檢視方式顯示為空白圖表。
- 動態圖表比例尺是一種呈現輔助工具。當圖表達到頂端時，
  單獨出現這個情況，並不代表硬體限制已經達到。
- **趨勢**圖會將數值標準化，使其落在固定的 0 到 100 的顯示範圍內。
  顯示方向和相對運動，而非單獨的測量值。

## 狀態和閾值

快取中的指標定義包含可選的警告和臨界值。目前的預設值如下：

| 指標 | 警告 | 關鍵的 |
| --- | ---: | ---: |
| 熱感測器 | 70°C | 85°C |
| CPU 總體使用率和每個核心的使用率 | 80% | 95% |
| 標準化的每分鐘 CPU 負載量 | 80% | 95% |
| Linux 已用記憶體 | 80% | 90% |
| 已使用的 eMMC/NVMe 檔案系統 | 80% | 90% |

在有可用資料的情況下，沒有設定閾值的指標會顯示 `normal`。`unknown` 表示沒有有限的值存在；這並不表示該值為零。

在互動式 TUI 介面中，熱度分佈圖的折線圖為綠色；「概覽」溫度圖在 70°C 以下顯示為綠色，70°C 到 85°C 之間顯示為黃色，85°C 以上顯示為紅色。
舊版非 TUI 表格格式化工具在 45°C 以下顯示為青色，45°C 到 70°C 之間顯示為綠色，70°C 以上顯示為紅色，85°C 以上顯示為粗體紅色。

## 重設與持續性

快取資料儲存在 `/run` 目錄下，因此通常會在重新啟動時清除。歷史記錄、
電力會話平均值/峰值、電力軌道樣本/錯誤計數，以及程序差異基準值會在 Sentinel 守護程式重新啟動時重設。Sentinel 不會建立一個持久性的時間序列資料庫。
