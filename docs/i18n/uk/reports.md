# Звіти та експорт даних JSON.

Усі команди Sentinel зчитують дані з кешу демона, якщо команда `daemon` не виконує збір даних.

## Команди

| Команда | Вивід |
| --- | --- |
| `simaai-sentinel` | Інтерактивний режим відображення операцій на терміналі, що складається з п’яти панелей. |
| `simaai-sentinel table` | Постійно оновлювана таблиця показників із відображенням поточного значення, одиниці вимірювання та статусу граничного значення. |
| `simaai-sentinel table --once` | Один знімок таблиці, який підходить для журналів. |
| `simaai-sentinel export` | Завершіть створення кешованого документа у вказаному форматі JSON. |
| `simaai-sentinel sensors` | Назви метрик, групи, одиниці вимірювання, порогові значення та описи, надані збирачем даних. |
| `simaai-sentinel status` | Версія Sentinel, час останньої зміни кешу, час/вік останнього зразка, розмір історії, кількість показників і найважливіші помилки головного демона. |

Використовуйте `--cache PATH`, щоб читати або записувати дані в кеш, відмінний від кешу за замовчуванням. Інтервали оновлення інтерфейсу користувача/таблиці впливають лише на відображення. `daemon --interval SEC` змінює звичайний цикл роботи системи/кешу; PMBus, а також збирачі даних про температуру та процеси зберігають власні цикли роботи.

## Зберегти документ у кеші.

`simaai-sentinel export` виводить таку структуру верхнього рівня:

| Поле | Значення. |
| --- | --- |
| `schema` | Версія схеми кешу. Наразі `1`. |
| `version` | Версія пакета Sentinel, яка створила кеш. |
| `updated_at` | Час UTC, коли було записано дані в кеш. |
| `metrics` | Означення для всіх показників, які були доступні на момент запуску демона. |
| `latest` | Найновіший зразок кешу або `null`, якщо зразок ще не існує. |
| `samples` | Збережено історію даних у кільцевому буфері в хронологічному порядку. |
| `processes` | Останній збережений знімок поточного процесу, оновлюється кожні п’ять секунд. |
| `power` | Статус модуля збору енергії та лічильники для кожної окремої лінії, або `null` для застарілої/несумісної версії кешу. |
| `errors` | Найважливіші повідомлення від системного демона. Зазвичай, помилки, пов’язані з лінією живлення, відображаються у розділі `power.last_error`. |

## Визначення метрик.

Кожен запис `metrics` містить:

| Поле | Значення. |
| --- | --- |
| `key` | Стабільне машинно-зчитуване ім’я, що використовується в `Sample.values`. |
| `label` | Довга назва, зрозуміла для людини. |
| `short` | Компактна мітка для інтерфейсу користувача/таблиці. |
| `group` | Категорія підсистеми. |
| `unit` | Блок відображення. |
| `description` | Зведена інформація про вимірювання, надана особою, яка здійснює збір даних. |
| `warn` | Необов’язковий поріг спрацювання попередження. |
| `critical` | Необов’язковий критичний поріг. |

Споживачі повинні пов’язувати приклади значень із відповідними визначеннями за допомогою `key`, а не за допомогою мітки чи позиції в масиві.

## Зразки

Кожен зразок містить:

- `timestamp`: мітка часу для колекції/кешу у форматі UTC;
- `values`: відображення ключа метрики на числове значення або `null`.

`null` означає, що колектор не надав жодного конкретного значення. Це не слід інтерпретувати як нуль. Ключ також може бути відсутнім, якщо підсистему не було налаштовано, наприклад, NVMe, коли `/media/nvme` не було змонтовано під час запуску демона.

## Обробляйте записи.

Кожен запис процесу містить `pid`, `name`, `cpu_pct`, `rss_mb` і, за потреби, `cpu_core`. Див. розділ [Системна панель](panels/system.md) для отримання інформації про обмеження щодо обчислень і вибору.

## Статус живлення / Статус живлення пристрою.

Об’єкт `power` містить:

| Поле | Значення. |
| --- | --- |
| `profile` | Визначено профіль рейки, наприклад, `modalix_som` або `modalix_dvt`. |
| `sample_interval_ms` | Налаштовано інтервал дискретизації PMBus. |
| `duration_seconds` | Час, що минув від початку накопичення енергії. |
| `valid_samples` | Проходить, якщо принаймні одна спроба завершується успішно. |
| `failed_samples` | Тести проходять, але без успішних результатів для окремих елементів. |
| `last_sample_valid` | Чи зчитала остання версія PMBus хоча б одну лінію живлення. |
| `last_error` | Зведений текст помилок для елементів, які не пройшли перевірку під час останнього запуску, або `null`. |
| `rails` | Мітка для кожної окремої ділянки рейки, метричний ключ, значення потужності, отримане під час останнього успішного вимірювання, кількість успішних зразків і кількість помилок. |

Перегляньте [Панель керування](panels/power.md) перед використанням цих полів для автоматизованого порівняння; часткове зчитування даних впливає на загальну можливість порівняння.

## Атомарність і збереження даних.

Демон створює тимчасовий файл, очищає його та перейменовує, замінюючи попередній файл у кеші. Таким чином, користувачі повинні бачити або попередній повний набір даних, або новий повний набір даних. Кеш містить інформацію про поточний стан і короткий огляд історії, але не є надійним журналом аудиту. Експортуйте його у зовнішнє сховище, коли потрібні постійні докази.
