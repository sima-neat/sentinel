# Панель для зберігання даних і підключення до мережі.

Панель «Пам’ять/Мережа» відображає обсяг пам’яті та загальну кількість операцій вводу-виводу для основного модуля eMMC,
додаткового накопичувача NVMe, змонтованого в `/media/nvme`, та сукупні показники мережевих лічильників, що не використовують цикл зворотного зв’язку.

## Обсяг файлової системи.

| Поле | Джерело та обчислення. |
| --- | --- |
| Використано eMMC / використано МБ | `statvfs("/")` |
| NVMe: використано / загальний обсяг (МБ) | `statvfs("/media/nvme")`, лише якщо вказаний шлях є точкою монтування. |

Sentinel обчислює:

```text
total = f_blocks × f_frsize
available = f_bavail × f_frsize
used = total - available
used_pct = used / total × 100
```

Оскільки `f_bavail` – це вільний простір, доступний для процесу без особливих привілеїв, зарезервовані блоки файлової системи впливають на відображене значення використаного простору. `MB` використовує бінарне перетворення в МіБ.

Визначення метрик NVMe додаються лише тоді, коли `/media/nvme` виявляється як змонтований диск під час запуску демона. Перезапустіть Sentinel після монтування або розмонтування диска, щоб набір доступних метрик відповідав системі.

## Введення/виведення даних з диска.

Sentinel визначає батьківський блоковий пристрій для точки монтування, використовуючи дані з `/proc/mounts`, зчитує лічильники секторів з `/proc/diskstats`, множить на апаратний розмір сектора пристрою та ділить різницю в байтах на проміжок часу між зчитуваннями.

Таким чином, показники швидкості читання/запису описують весь батьківський блоковий пристрій, а не лише файли, до яких здійснюється доступ через відображену файлову систему. Інші розділи або користувачі, які використовують той самий пристрій, також можуть впливати на ці показники.

Якщо визначення відповідності між точкою монтування та пристроєм не вдається, Sentinel використовує евристичний метод на основі назви пристрою:

- eMMC: перший цілісний пристрій `mmcblk*`;
- NVMe: перший повноцінний пристрій `nvme*`.

У першому зразку немає попереднього базового значення лічильника, і відображається нульова швидкість.
Скидання лічильника та заміна пристрою здійснюються за допомогою насиченого віднімання,
тому вони не створюють від’ємну швидкість.

В інтерфейсі користувача швидкість відображається як `MB/s`, але під час обчислення значення ділиться на 1024 двічі, тому воно еквівалентне MiB/с.

## Мережеві поля

| Поле | Обчислення. |
| --- | --- |
| Мережевий приймач (RX). | Сума різниць отриманих байтів від `/proc/net/dev` для кожного інтерфейсу, відмінного від інтерфейсу зворотного зв’язку, поділено на проміжок часу, що минув. |
| Мережевий передавач | Сума різниць кількості переданих байтів від `/proc/net/dev` для кожного інтерфейсу, відмінного від інтерфейсу зворотного зв’язку, поділено на проміжок часу, що минув. |
| Мережева діаграма. | RX + TX. |

До агрегації входять фізичні інтерфейси, мости, VLAN, тунелі та віртуальні пристрої Ethernet, якщо вони присутні. Отже, один і той самий трафік може бути враховано на кількох рівнях, наприклад, один раз на фізичному інтерфейсі та знову на мості. Це активність системного інтерфейсу, а не обов’язково пропускна здатність зовнішнього кабелю.

Інтерфейси повинні бути присутніми в послідовних вибірках, щоб впливати на зміну показників. Перша мережева вибірка показує нуль. Ключі закінчуються на `_mbps`, але одиниця вимірювання еквівалентна MiB/с, а не мегабітам за секунду.
