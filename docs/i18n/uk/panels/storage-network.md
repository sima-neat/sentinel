# Панель для зберігання даних і мережевих підключень.

На панелі «Пам’ять/Мережа» відображається обсяг пам’яті та загальна кількість операцій введення-виведення для вбудованої пам’яті eMMC,
необов’язкового NVMe-накопичувача, змонтованого в `/media/nvme`, сукупні показники мережевих інтерфейсів (без урахування локальних),
а також показники використання каналу зв’язку за маршрутом за замовчуванням для локальних агентів.

## Обсяг файлової системи.

| Поле | Джерело та обчислення |
| --- | --- |
| використано eMMC / використано МБ | `statvfs("/")` |
| NVMe, використано / використано МБ | `statvfs("/media/nvme")`, лише якщо цей шлях є точкою монтування. |

Sentinel обчислює:

```text
total = f_blocks × f_frsize
available = f_bavail × f_frsize
used = total - available
used_pct = used / total × 100
```

Оскільки `f_bavail` – це вільний простір, доступний для непривілейованого процесу, зарезервовані блоки файлової системи впливають на відображене значення використаного простору. `MB` використовує бінарне перетворення в МіБ.

Визначення метрик NVMe додаються лише тоді, коли `/media/nvme` виявляється як змонтований диск під час запуску демона. Перезапустіть Sentinel після монтування або розмонтування диска, щоб набір доступних метрик відповідав системі.

## Введення-виведення даних з диска.

Sentinel визначає батьківський блоковий пристрій для точки монтування, використовуючи дані з `/proc/mounts`, зчитує лічильники секторів з `/proc/diskstats`, множить на апаратний розмір сектора пристрою та ділить різницю в байтах на проміжок часу між зчитуваннями.

Таким чином, показники швидкості читання/запису описують весь батьківський блоковий пристрій, а не лише файли, до яких здійснюється доступ через відображену файлову систему. Інші розділи або користувачі, які використовують той самий пристрій, також можуть впливати на ці показники.

Якщо не вдається визначити зв’язок між точкою монтування та пристроєм, Sentinel використовує евристичний метод на основі назви пристрою:

- eMMC: перший цілісний пристрій `mmcblk*`;
- NVMe: перший повноцінний пристрій `nvme*`.

У першому зразку немає попереднього значення лічильника, тому відображається нульова швидкість.
Скидання лічильника та заміна пристрою обробляються за допомогою насиченого віднімання,
тож вони не призводять до від’ємної швидкості.

В інтерфейсі користувача швидкість відображається як `MB/s`, але під час обчислення значення ділиться на 1024 двічі, тому фактично це еквівалентно MiB/с.

## Мережеві поля

| Поле | Обчислення |
| --- | --- |
| Мережевий прийом: | Сума змін кількості отриманих байтів з `/proc/net/dev` для кожного інтерфейсу, відмінного від інтерфейсу зворотного зв’язку, поділена на минулий час. |
| Мережевий трафік (TX): | Сума змін кількості переданих байтів з `/proc/net/dev` для кожного інтерфейсу, відмінного від інтерфейсу локальної петлі, поділена на проміжок часу. |
| Мережева схема | RX + TX. |
| Вхідний/вихідний канал зв’язку | Різниця між кількістю отриманих і переданих байтів для інтерфейсу, обраного за допомогою маршруту IPv4 за замовчуванням, поділена на минулий час. |
| Завантаження каналу зв’язку (прийом/передача) | Швидкість передачі даних у каналі зв’язку в бітах за секунду, поділена на швидкість з’єднання мережевого інтерфейсу з `/sys/class/net/<interface>/speed`. |

Агрегація включає фізичні інтерфейси, мости, VLAN, тунелі та віртуальні Ethernet-пристрої, якщо вони присутні. Таким чином, один і той самий трафік може враховуватися на кількох рівнях, наприклад, один раз на фізичному інтерфейсі та знову на мості. Це активність системного інтерфейсу, а не обов’язково пропускна здатність зовнішнього кабелю.

Інтерфейси повинні існувати в послідовних вибірках, щоб враховуватися при обчисленні дельти. Перша мережева вибірка показує нуль. Ключі закінчуються на `_mbps`, але одиниця вимірювання – еквівалент MiB/с, а не мегабіт за секунду.

Локальний API також надає доступ до `network_rx_bytes_per_second`, `network_tx_bytes_per_second`, `network_rx_utilization_percent` та `network_tx_utilization_percent`. Ці однозначні показники вимірюють лише інтерфейс за замовчуванням, що дозволяє уникнути подвійного підрахунку, можливого в агрегованих лічильниках інтерфейсів UI. Інформація про завантаження недоступна, коли Linux не повідомляє про позитивну швидкість з’єднання (наприклад, для деяких віртуальних або бездротових інтерфейсів).
