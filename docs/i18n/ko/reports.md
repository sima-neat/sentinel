# 보고서 및 JSON 내보내기

모든 Sentinel 명령어는 `daemon` 명령어가 수집기를 실행 중이 아닌 한 데몬 캐시를 참조합니다.

## 명령어

| 명령어 | 출력 |
| --- | --- |
| `simaai-sentinel` | 대화형 5개의 패널로 구성된 터미널 작동 방식 보기. |
| `simaai-sentinel table` | 현재 값, 단위 및 임계값 상태를 포함하여 지속적으로 업데이트되는 지표 테이블입니다. |
| `simaai-sentinel table --once` | 로그에 적합한 단일 테이블 스냅샷입니다. |
| `simaai-sentinel export` | 형식에 맞춰 캐시 문서를 완성합니다. JSON |
| `simaai-sentinel sensors` | 측정 지표 이름, 그룹, 단위, 임계값, 그리고 수집기가 제공하는 설명. |
| `simaai-sentinel status` | Sentinel 버전, 캐시 타임스탬프, 최신 샘플 시간/경과 시간, 히스토리 크기, 메트릭 수, 최상위 데몬 오류. |

기본 캐시가 아닌 캐시를 읽거나 쓰려면 `--cache PATH`를 사용합니다. UI/테이블 새로 고침 간격은 화면 표시 기능에만 영향을 미칩니다. `daemon --interval SEC`는 일반 시스템/캐시 주기를 변경하고, PMBus, 온도, 프로세스 수집기는 자체 주기를 유지합니다.

## 문서를 캐시합니다.

`simaai-sentinel export`는 최상위 구조를 다음과 같이 출력합니다.

| 필드 | 의미 |
| --- | --- |
| `schema` | 캐시 스키마 버전입니다. 현재 `1`. |
| `version` | 캐시를 작성한 Sentinel 패키지 버전입니다. |
| `updated_at` | 캐시 페이로드가 기록된 UTC 시간입니다. |
| `metrics` | 데몬이 시작될 때 사용 가능한 모든 지표에 대한 정의입니다. |
| `latest` | 가장 최신의 캐시 샘플 또는 샘플이 존재하기 전에 `null` |
| `samples` | 시간 순서대로 정렬된 링 버퍼 기록을 유지합니다. |
| `processes` | 최신 보존된 프로세스 스냅샷이며, 5초마다 새로 고침됩니다. |
| `power` | 전원 수집기의 상태 및 레일별 카운터 또는 이전 버전 또는 호환되지 않는 캐시의 경우 `null`. |
| `errors` | 최상위 데몬 메시지입니다. 전원 공급 장치 오류는 일반적으로 `power.last_error`에 기록됩니다. |

## 지표 정의

각 `metrics` 항목에는 다음이 포함됩니다.

| 필드 | 의미 |
| --- | --- |
| `key` | `Sample.values`에서 사용되는 안정적인 기계 판독 가능한 이름입니다. |
| `label` | 사람이 읽기 쉬운 긴 이름입니다. |
| `short` | 간결한 UI/테이블 레이블입니다. |
| `group` | 하위 시스템 범주. |
| `unit` | 디스플레이 장치. |
| `description` | 수집가가 제공한 측정 요약. |
| `warn` | 선택적 경고 임계값입니다. |
| `critical` | 선택 사항인 임계값. |

사용자는 레이블이나 배열 위치가 아닌, `key`를 사용하여 샘플 값을 정의에 연결해야 합니다.

## 샘플

각 샘플에는 다음이 포함됩니다.

- `timestamp`: UTC 기준 데이터 수집/캐시 시간;
- `values`: 지표 키를 숫자 또는 `null`과 연결합니다.

`null`은 수집기가 유한한 값을 생성하지 않았음을 의미합니다. 이를 0으로 해석해서는 안 됩니다. 하위 시스템이 구성되지 않은 경우(예: `/media/nvme`가 데몬 시작 시 마운트되지 않은 경우) 키가 없을 수도 있습니다.

## 처리 기록

각 프로세스 기록에는 `pid`, `name`, `cpu_pct`, `rss_mb` 및 선택적인 `cpu_core`가 포함됩니다. 계산 및 선택 제한 사항은 [시스템 패널](panels/system.md)을 참조하십시오.

## 전원 상태

`power` 객체는 다음을 포함합니다.

| 필드 | 의미 |
| --- | --- |
| `profile` | `modalix_som` 또는 `modalix_dvt`와 같은 레일 프로파일이 감지되었습니다. |
| `sample_interval_ms` | PMBus 샘플링 간격을 설정했습니다. |
| `duration_seconds` | 전력 축적이 시작된 이후 경과 시간입니다. |
| `valid_samples` | 최소 하나 이상의 레일이 성공적으로 통과하면 합격입니다. |
| `failed_samples` | 성공적인 레일 연결이 하나도 없을 때 통과합니다. |
| `last_sample_valid` | 최신 PMBus 패스가 최소한 하나의 전압 레일을 읽었는지 확인합니다. |
| `last_error` | 최근 테스트에서 실패한 레일에 대한 오류 메시지를 결합하거나, `null`. |
| `rails` | 레일별 라벨, 메트릭 키, 마지막 성공적인 와트 값, 성공적인 샘플 수, 오류 수. |

자동 비교를 위해 이러한 필드를 사용하기 전에 [전원 패널](panels/power.md)을 확인하십시오. 부분적인 레일 읽기는 전체 비교 가능성에 영향을 미칩니다.

## 원자성과 보존성

데몬은 임시 파일을 생성하고, 내용을 기록한 후, 캐시를 덮어쓰면서 파일 이름을 변경합니다. 따라서, 데이터를 읽는 사용자는 이전의 완전한 페이로드 또는 새로운 완전한 페이로드 중 하나를 보게 됩니다. 캐시는 영구적인 감사 로그가 아닌 현재 상태 및 단기 기록 보고서입니다. 지속적인 증거가 필요한 경우 외부로 내보내십시오.
