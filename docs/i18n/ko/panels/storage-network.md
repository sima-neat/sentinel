# 저장 장치 및 네트워크 패널

스토리지/네트워크 패널은 루트 eMMC의 용량 및 전체 장치 I/O, `/media/nvme`에 마운트된 선택적 NVMe 스토리지, 집계된 비 루프백 네트워크 카운터, 그리고 로컬 에이전트의 기본 경로 업링크 사용률을 보고합니다.

## 파일 시스템 용량

| 필드 | 출처 및 계산 방법 |
| --- | --- |
| 사용 중인 eMMC / 사용 중인 MB | `statvfs("/")` |
| NVMe 사용량 / 사용된 MB | `statvfs("/media/nvme")`, 해당 경로가 마운트 지점일 때만 표시 |

Sentinel은 다음을 계산합니다.

```text
total = f_blocks × f_frsize
available = f_bavail × f_frsize
used = total - available
used_pct = used / total × 100
```

`f_bavail`은 권한이 없는 프로세스에 할당된 사용 가능한 공간이므로, 예약된 파일 시스템 블록은 표시되는 사용량 값에 영향을 미칩니다. `MB`는 이진 MiB 변환 방식을 사용합니다.

`/media/nvme`가 데몬 시작 시 마운트된 것으로 감지될 때만 NVMe 메트릭 정의가 추가됩니다. 드라이브를 마운트하거나 언마운트한 후에는 Sentinel을 다시 시작하여 사용 가능한 메트릭 세트가 시스템과 일치하도록 해야 합니다.

## 디스크 입출력

Sentinel은 `/proc/mounts`에서 마운트의 상위 블록 장치를 확인하고, `/proc/diskstats`에서 섹터 카운터를 읽어 들여, 장치 하드웨어 섹터 크기로 곱하고, 바이트 변화량을 경과 시간으로 나누어 계산합니다.

따라서 읽기/쓰기 속도는 표시된 파일 시스템을 통해 액세스되는 파일뿐만 아니라 전체 상위 블록 장치를 나타냅니다. 다른 파티션이나 동일한 장치를 사용하는 다른 사용자가 기여할 수 있습니다.

마운트-장치 확인에 실패하면 Sentinel은 장치 이름 휴리스틱을 사용합니다.

- eMMC: 첫 번째 전체 `mmcblk*` 장치;
- NVMe: 최초의 완전한 `nvme*` 장치.

첫 번째 샘플은 이전 카운터 기준값이 없으므로 0의 속도를 보고합니다.
카운터 재설정 및 장치 교체는 포화 뺄셈으로 처리되므로 음수 속도가 생성되지 않습니다.

UI에는 속도가 `MB/s`로 표시되지만, 계산에서는 1024로 두 번 나누므로 MiB/s와 동일한 값을 나타냅니다.

## 네트워크 필드

| 필드 | 계산 |
| --- | --- |
| 네트워크 RX: | 각 논루프백 인터페이스에 대해 `/proc/net/dev`에서 수신된 바이트의 변화량 합계를 경과 시간으로 나눈 값입니다. |
| 네트워크 TX | 각 논 루프백 인터페이스에 대해 `/proc/net/dev`에서 가져온 전송 바이트 변화량의 합계를 경과 시간으로 나눈 값입니다. |
| 네트워크 차트 | RX + TX. |
| 업링크 RX/TX | IPv4 기본 경로로 선택된 인터페이스에 대한 수신/송신 바이트 차이, 경과 시간으로 나눈 값. |
| 업링크 RX/TX 사용률 | 초당 비트 단위의 방향성 업링크 속도를 해당 인터페이스 링크 속도로 나눈 값 `/sys/class/net/<interface>/speed`. |

집계에는 물리적 인터페이스, 브리지, VLAN, 터널 및 가상 이더넷 장치가 포함됩니다(존재하는 경우). 따라서 동일한 트래픽이 여러 계층에서 계산될 수 있습니다. 예를 들어, 물리적 인터페이스에서 한 번, 브리지에서 다시 한 번 계산될 수 있습니다. 이는 시스템 인터페이스 활동이며, 반드시 외부 케이블을 통한 처리량을 의미하는 것은 아닙니다.

인터페이스는 델타 값에 기여하기 위해 연속적인 샘플에 존재해야 합니다. 첫 번째 네트워크 샘플은 0을 보고합니다. 키는 `_mbps`로 끝나지만, 단위는 초당 메가비트가 아닌 MiB/s와 같습니다.

로컬 API는 또한 `network_rx_bytes_per_second`, `network_tx_bytes_per_second`, `network_rx_utilization_percent` 및 `network_tx_utilization_percent`를 노출합니다. 이러한 명확한 메트릭은 집계 UI 카운터에서 발생할 수 있는 중복 계산을 방지하기 위해 기본 경로 인터페이스만 측정합니다. Linux가 양수 링크 속도를 보고하지 않는 경우(예: 일부 가상 또는 무선 인터페이스) 사용률을 계산할 수 없습니다.
